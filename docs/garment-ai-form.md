# فرم لباس با JSON اجباری و انتقال دستی هوش مصنوعی

این سند جایگزین توضیح «JSON اختیاری» در راهنمای قدیمی JSON است.

## نصب

پچ افزایشی `bootic-ai-form.patch` روی commit `47e9ffe` (نسخهٔ دارای JSON) ساخته شده و با نصب بودن پچ `bootic-shoulder-edge-fit.patch` نیز سازگار است. شامل تکرار پچ JSON یا اصلاح شانه نیست.

```sh
git apply --check ./bootic-ai-form.patch
git apply ./bootic-ai-form.patch
```

فقط پس از موفقیت دستور اول، دومی را اجرا کنید. مانند همیشه پس از اعمال، APK جدید را بیلد کنید. این پچ کلید امضا، شناسهٔ برنامه، شمارهٔ نسخه یا گردش انتشار را تغییر نمی‌دهد.

## جریان کار

۱. در فرم لباس عکس اصلی روبرو را انتخاب کنید یا با دوربین عکس بگیرید. عکس بدون حذف پس‌زمینه وارد می‌شود؛ جهت EXIF اصلاح و نسبت کادر حفظ می‌شود.
۲. «کپی سیستم پرامپت» را بزنید. پرامپت شامل شناسه/ابعاد همین عکس، تمام فیلدهای فعال فرم، گزینه‌های دقیق مشخصه‌های سفارشی و اطلاعات دستی فعلی است.
۳. «اشتراک عکس مرجع» روی اندروید همان عکس واردشده را در پنجرهٔ اشتراک سیستم باز می‌کند. آن را به هوش مصنوعی دلخواه بدهید و پرامپت کپی‌شده را هم بچسبانید. اپ خودش عکس یا پرامپت را ارسال نمی‌کند و API/کلید هوش مصنوعی نمی‌خواهد.
۴. پاسخ کامل را در «پاسخ کامل هوش مصنوعی (JSON)» بچسبانید و «اعمال JSON و پرکردن فرم» را بزنید.
۵. اطلاعات فرم، مشخصات سفارشی و JSON پرو زنده پر می‌شوند. خروجی به‌صورت پیش‌نویس ذخیره می‌شود؛ مشخصات را بررسی کنید و «ثبت در کاتالوگ» را بزنید.

ورودی اجباری AI یک شیء با `schema_version: bootic.garment-import/1` و سه بخش `photo_id`، `garment` و `try_on` است. `try_on` همان قرارداد عددی قبلی `bootic.garment-metadata/0.1` است. فقط این قسمت به رندر اندرویدی داده می‌شود؛ پاسخ کامل نیز کنار لباس ذخیره می‌شود.

## اعتبارسنجی و نگهداری اطلاعات

- ثبت نهایی و پرو زنده بدون JSON معتبر و عکس اصلی ممکن نیست. پیش‌نویس ناقص برای انجام مراحل بالا مجاز است.
- پاسخ مربوط به شناسهٔ عکس دیگر یا ابعاد ناسازگار رد می‌شود. تعویض/حذف عکس روبرو، JSON و پاسخ قبلی را پاک و لباس را پیش‌نویس می‌کند؛ مشخصات دستی لباس باقی می‌مانند.
- پاسخ قبل از اعمال بررسی می‌شود: مختصات و چندضلعی‌ها، نوع مشخصه‌های فرم، گزینه‌های انتخابی، محدودهٔ عددی و سازگاری قیمت تخفیف. پاسخ نامعتبر بخشی از فرم را تغییر نمی‌دهد.
- مقدار `null` یعنی نامعلوم و مقدار دستی قبلی را پاک نمی‌کند. مقدار واقعی صفر یا false حفظ می‌شود. پاک‌کردن دستی فیلدها همچنان ممکن است.
- قیمت و تخفیف بر حسب تومان، اندازه‌ها بر حسب میلی‌متر هستند. قیمت، موجودی، اندازهٔ واقعی و اطلاعات نامعلوم از ظاهر عکس حدس زده نمی‌شوند؛ اپ یک عکس را به اندازه‌گیری فیزیکی معتبر تبدیل نمی‌کند.
- گروه لباس شامل مردانه، زنانه، دخترانه، پسرانه و یونیسکس است. «نامشخص» برای دادهٔ قدیمی یا ابهام در تشخیص باقی است؛ یونیسکس پیش‌فرضِ نامعلوم نیست.
- دادهٔ لباس‌های قدیمی حذف نمی‌شود و مهاجرت دیتابیس نیاز نیست. لباس قدیمی بدون JSON/عکس اصلی، در فهرست و ویرایش باقی است اما در پرو زنده نمی‌آید. برای استفاده، عکس اصلی و JSON را تکمیل کنید. آرشیو کردن رکورد قدیمی همچنان ممکن است.
- JSON رندر به‌صورت دستی هم قابل ویرایش است. فیلد پاسخ کامل فقط با دکمهٔ اعمال تفسیر می‌شود؛ چسباندن پاسخ به‌تنهایی فرم را تغییر نمی‌دهد.

## حذف سرویس شفاف‌سازی

دکمه و مسیر خودکار حذف پس‌زمینه، کلاس `GarmentCutout`، وابستگی ML Kit Subject Segmentation و اعلان دانلود آن از Manifest حذف شدند. پردازش عکس و ذخیرهٔ آن سرویس شفاف‌سازی ندارد. عکس‌های قدیمی عمداً دستکاری نمی‌شوند.

ساخت ماسک از چندضلعی‌های JSON داخل رندر پرو باقی است؛ این همان استفاده از مرزهای JSON است و سرویس مستقل حذف پس‌زمینه نیست. ماسک بدن مشتری در پچ شانه نیز مستقل از عکس محصول است و حذف نمی‌شود.

## آزمون

ابزار `tool/check_ai_import.dart` قرارداد کامل، پرکردن مشخصات، حفظ null/صفر/false، همهٔ گروه‌های لباس، ذخیره/بازیابی، دادهٔ قدیمی، الزام JSON، عکس اشتباه، ابعاد/نقاط نامعتبر، گزینهٔ سفارشی، قیمت/موجودی/اندازهٔ نامعتبر و عدم تغییر جزئی فرم را بررسی می‌کند. همان ابزار در مجموعهٔ Flutter test نیز فراخوانی می‌شود. ابزار قبلی `tool/check_render_metadata.dart` نیز نگه داشته شده است.

بیلد کامل Flutter/APK و رفتار واقعی کلیپ‌بورد و پنجرهٔ اشتراک روی گوشی باید بررسی شود؛ این‌ها با آزمون خالص Dart اثبات نمی‌شوند.
