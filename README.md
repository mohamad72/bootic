# بوتیک — نسخه محلی Android

این مخزن بر اساس `implementation-spec-fa.md` شروع شده است. محدوده فعلی فقط یک اپ Flutter برای بوتیک است. تصمیم‌های تغییر دامنه و وضعیت واقعی هر بسته در [`docs/implementation-plan.md`](docs/implementation-plan.md) و [`IMPLEMENTATION_STATUS.md`](IMPLEMENTATION_STATUS.md) ثبت شده‌اند.

در این نسخه می‌توانید نام بوتیک را ثبت کنید، با کد ثابت `22222` وارد شوید، لباس و قیمت/موجودی/متادیتای سفارشی را نگه دارید، چهار عکس لباس را از گالری در فضای خصوصی اپ ذخیره کنید، پیش‌نویس و آرشیو بسازید و کاتالوگ را دستی به مشتری نشان دهید. ورودی کد و عدد، ارقام فارسی/عربی را هم می‌پذیرد. دیتابیس Drift/SQLite و عکس‌ها هر دو محلی هستند.

دکمه تحلیل هوش مصنوعی خطای واضح می‌دهد و هیچ API را فراخوانی نمی‌کند. مرور کاتالوگ، پرو زنده نیست. صفحهٔ آزمایشی پیش‌نمایش، دوربین جلو را با CameraX باز می‌کند و با مدل محلی MediaPipe جای تقریبی عکس لباس را از شانه و لگن حساب می‌کند؛ تنظیم دستی هم دارد. لباس‌ها به‌ترتیب نمایش داده می‌شوند؛ علامت شست بالا/پایین یا دکمه‌های لمسی رأی را برای جلسه ثبت می‌کنند و لباس بعدی را می‌آورند. قیمت لباس گوشهٔ تصویر گوشی و نمایشگر مستقل Android دیده می‌شود. در فرم لباس نیز عکس‌برداری با دوربین پشت اضافه شده است. کد بومی دوربین و علامت دست هنوز کامپایل یا روی گوشی و پروژکتور آزموده نشده است. عکس لباس JPEG با پس‌زمینه است و برش/شبیه‌سازی پارچه ندارد. اپ ادمین و سرور نداریم. کد ثابت یک قفل ساده محلی است. داده‌ها با حذف نصب یا پاک‌کردن داده برنامه حذف می‌شوند؛ بک‌آپ و همگام‌سازی وجود ندارد.

برای اجرا از پوشه `apps/store_app`:

```powershell
flutter pub get
dart run build_runner build
flutter analyze --no-pub
flutter test --no-pub
flutter run -d <android-device-id>
```

ساخت APK: `flutter build apk --debug --no-pub`. روی این میزبان Android SDK 36 و NDK 28.2.13676358 موجود نیست؛ نتیجه دقیق تلاش ساخت در فایل وضعیت ثبت شده است. آزمون دستی دوربین/نمایشگر در [`docs/live-preview-device-check.md`](docs/live-preview-device-check.md) آمده است. هیچ APK انتشار با کلید ثابت تولید نشده است. فونت Vazirmatn و مجوز OFL آن در `apps/store_app/assets/fonts` قرار دارند.

برای ساخت ابری APK آزمایشی، workflow گیت‌هاب در `.github/workflows/android-debug.yml` با هر push به `main` اجرا می‌شود؛ می‌توانید آن را از زبانه `Actions` و گزینهٔ `Run workflow` هم دستی اجرا کنید. پس از موفقیت، در صفحهٔ همان اجرا بخش `Artifacts` فایل `bootic-debug-apk` را دانلود کنید. APK با کلید debug ساخته می‌شود و برای انتشار فروشگاهی نیست. نتیجهٔ ساخت ابری را تا اجرای موفق در GitHub Actions تأییدشده حساب نکنید.
